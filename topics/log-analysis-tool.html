The Problem

Support teams spend significant time manually analyzing system logs and databases to diagnose issues. This process is time-consuming, error-prone, and requires deep technical knowledge to trace through complex log files in Kibana Elasticsearch and database states simultaneously.

I built an internal tool that automates this process using a multi-agent workflow, allowing support teams to quickly gather and analyze system information from both logs and databases without writing complex queries manually.

Multi-Agent Workflow Architecture

The tool implements a collaborative multi-agent system where specialized agents work together to provide comprehensive system analysis:

Agent Communication Workflow

SQL Agent: Converts natural language questions into database queries using LangChain's SQL Agent framework. This agent retrieves structured data from relational databases, such as user information, system configurations, and transaction records.

Logs Analysis Agent: Connects to Kibana Elasticsearch to retrieve real-time log data. This agent queries indexed logs to understand what is happening in the system at runtime, including errors, warnings, and system events.

Agent Coordination: The agents communicate together in an orchestrated workflow. When a support question is asked, the system determines which agents need to be involved. For example, investigating a user issue might require the SQL Agent to fetch user details from the database while the Logs Analysis Agent retrieves recent error logs from Kibana for that user.

Key Insight: By combining database state with real-time log analysis, the tool provides a complete picture of system behavior, reducing diagnosis time by 35%.

Technical Considerations

Schema Synchronization: A challenge with database tools is keeping mappings current. One approach is integrating with version control systems to automatically detect when schema files change and trigger mapping updates.

Static vs. Dynamic Mappings: Using static mappings (like .hbm.xml files) can improve performance by reducing repeated schema lookups, though this requires a synchronization mechanism to stay current.

Elasticsearch Integration: The Logs Analysis Agent uses Elasticsearch queries to filter and retrieve relevant log entries. This requires careful query construction to handle the semi-structured nature of log data and ensure efficient searches across large log volumes.

Note: LangChain's SQLDatabaseToolkit provides built-in methods for table discovery and schema retrieval, which simplifies the SQL Agent implementation.
